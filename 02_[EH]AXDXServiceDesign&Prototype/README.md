## 5. [부록 3] AI 생성 코드 비판적 리뷰 체크리스트

1. 데이터 입력 및 무결성 검증 (Data Input & Integrity)

    - [ ] 프론트엔드 검증에만 의존하는가. UI 수준의 검증 외에, 백엔드 또는 데이터 저장 단계(Repository)에서 교차 검증 로직이 구현되었는지 확인한다.

    - [ ] XSS(Cross-Site Scripting) 취약점이 있는가. 사용자 입력값을 화면에 렌더링할 때 정제(Sanitization) 과정이 있는지 점검한다. 특히 React의 dangerouslySetInnerHTML 등이 검증 없이 사용되었는지 주의한다.

    - [ ] 인젝션(Injection) 방어 처리가 되었는가. 데이터 쿼리 시 단순 문자열 결합이 아닌, 파라미터화된(Parameterized) 처리 방식을 사용하는지 검토한다.

2. 권한 및 민감 정보 보호 (Authorization & Secrecy)

    - [ ] 인가(Authorization) 로직이 누락되었는가. 로그인한 사용자가 타인의 데이터(예: 다른 학생의 과제 목록)에 접근하거나 수정할 수 없는지 확인한다. (IDOR 취약점 검증)

    - [ ] 민감 정보가 하드코딩되었는가. API 키, 토큰, 데이터베이스 URL 등이 소스 코드에 직접 작성되지 않고 환경변수(.env)로 분리되었는지 점검한다.

3. 비즈니스 로직 및 엣지 케이스 (Business Logic & Edge Cases)

    - [ ] AI가 요구사항을 자의적으로 축소했는가. 테스트를 통과하기 위해 조건문을 정교하게 짜는 대신, 특정 상황에 맞는 하드코딩된 결과값만 반환하도록 로직을 우회했는지 점검한다.

    - [ ] 비동기 예외 처리가 통제되는가. async/await 또는 Promise 사용 시 try-catch 블록이 존재하는지, 네트워크 실패 시 사용자에게 적절한 상태(에러 메시지)를 반환하는지 확인한다.

    - [ ] 경계값(Boundary Value) 처리가 정확한가. null, undefined, 빈 배열, 0, 극단적으로 긴 문자열 등의 입력이 들어왔을 때 시스템이 멈추지 않고 설계된 대로 방어하는지 검토한다.

4. 환각 및 시스템 안정성 (Hallucination & Stability)

    - [ ] 존재하지 않는 라이브러리를 호출하는가. 패키지 매니저(package.json)에 정의되지 않았거나, AI가 임의로 지어낸 가상의 모듈(Hallucination)을 임포트하고 있는지 확인한다.

    - [ ] 무한 루프나 과도한 호출 위험이 있는가. 컴포넌트 생명주기 관리(예: 잘못 설정된 useEffect 의존성 배열) 오류로 인해 불필요한 재렌더링이나 무한 API 요청이 발생하지 않는지 점검한다.
